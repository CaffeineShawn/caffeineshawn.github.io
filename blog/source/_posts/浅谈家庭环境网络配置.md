# 主路由配置

> [思路来源](https://beyondkmp.com/2023/03/11/ax6000-static-ip-router-config/#!)

参考文章的思路，在路由器官方固件支持的情况下，直接设置静态路由表即可
（实测H3C NX54无需以下配置）；

对于后台管理页面不支持设置静态路由的设备，可尝试解锁ssh，参考如下配置进行修改
- 如无法修改静态路由，可以手动DHCP，将网关指向旁路由（此方法访问国内站点时，会受限于旁路由的转发性能）


## 设置路由表

```bash
vim /etc/config/network
```

### 增加FakeIP段路由

```network
config route
	option interface 'lan'
	option target '198.18.0.0'
	option netmask '255.255.0.0'
	option gateway '替换成旁路由的IP地址'
```

## 修改防火墙

```bash
vim /etc/config/firewall
```

### 修改转发配置

```firewall
config defaults
	option syn_flood '0'
	option input 'ACCEPT'
	option output 'ACCEPT'
	option forward 'ACCEPT' # 这里需要从REJECT改成ACCEPT
	option drop_invalid '0' # 这里需要从1改成0

config zone
	option name 'lan'
	option network 'lan'
	option input 'ACCEPT'
	option output 'ACCEPT'
	option forward 'ACCEPT' # 这里需要从REJECT改成ACCEPT
```


## 应用配置
```bash
/etc/init.d/network restart
/etc/init.d/firewall restart
```

# OpenWRT配置

OpenClash劫持DNS服务，运行在FakeIP+Tun模式下，FakeIP段需与静态路由中设置的保持一致

个人觉得，采用FakeIP的优点如下：
- 通过静态路由表实现无感分流，只需修改客户端DNS即可实现代理
- 在远端进行DNS解析，减少RealIP时网络栈需要等待DNS结果，再建立链接的过程（一次RTT）

而对于FakeIP的缺点，即FakeIP失效问题，可以通过TTL=1解决

OpenClash插件在Tun模式下，会自动注入路由规则

```
198.18.0.0/16 dev utun scope link
```

使得来自主路由转发的FakeIP流量，能够进入旁路由的Tun网卡，从而被正确转发到Mihomo内核，完成后续的代理过程

# 内网服务配置

出于安全考虑，建议内网所有服务仅监听LAN地址，避免将任何内网服务暴露到公网

如果有远程访问内网的需求，建议自行配置VPN，下文以[Mihomo](https://wiki.metacubex.one/config/inbound/)为例
> 在糟糕的跨网访问环境下，建议使用TCP连接增强稳定性

```config.yaml
listeners:
  - name: AAA-in-ipv6 # 公网ipv6直连，需要主路由直接拨号
    type: # 选择带鉴权的协议
    port: # 选择高位端口
    listen: ::0 # ipv6通配，主路由需关闭ipv6防火墙，旁路由仅允许来自该端口的ipv6流量访问
```

再使用DDNS-GO，将旁路由分配到的ipv6公网地址解析到域名

## 内网穿透

这又引申出一个问题，在没有ipv6的环境下，如何访问内网服务？

- 一是通过cloudflared借助cf服务器进行中转，延迟较高，建议作为兜底
- 二是使用NATMap进行NAT打洞，延迟较低

> 注意：NATMap需要NAT1环境，主路由需要将DMZ主机设置为旁路由，否则可能需要考虑其他中转方式（cloudflared等）

下文以NATMap为例，介绍借助CF Worker和SubStore，实现自动更新节点为打洞后的地址（思路由Gemini生成，验证可行）

1. CF Worker配置

- 确保已在Settings中配置环境变量SECRET_TOKEN（密码），并绑定KV命名空间NATMAP_KV

```js
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    const userAgent = request.headers.get("User-Agent") || "";

    // 基础防爬：拦截空 UA 或明显脚本特征（放行 Sub-Store 和正常的手机客户端）
    if (!userAgent || (userAgent.includes("curl") && request.method === "GET")) {
        return new Response("Access Denied", { status: 403 });
    }

    // [GET] 供 Sub-Store 获取最新地址，路径: /sub?token=你的密码
    if (request.method === "GET" && url.pathname === "/sub") {
      const token = url.searchParams.get("token");
      if (token !== env.SECRET_TOKEN) {
        return new Response("Unauthorized", { status: 401 });
      }

      // 从 KV 数据库读取
      const address = await env.NATMAP_KV.get("natmap_address");
      if (!address) {
        return new Response("No node available yet.", { status: 404 });
      }
      
      return new Response(address, {
        headers: { "Content-Type": "text/plain; charset=utf-8" }
      });
    }

    // [POST] 供路由器 natmap 脚本推送更新，路径: /update
    if (request.method === "POST" && url.pathname === "/update") {
      const authHeader = request.headers.get("Authorization");
      
      // 验证 Bearer Token
      if (authHeader !== `Bearer ${env.SECRET_TOKEN}`) {
        return new Response("Unauthorized", { status: 401 });
      }

      const newAddress = await request.text();
      // 简单校验格式是否包含冒号 (IP:端口)
      if (!newAddress || !newAddress.includes(":")) {
        return new Response("Bad Request: Invalid format", { status: 400 });
      }

      // 写入 KV 数据库
      await env.NATMAP_KV.put("natmap_address", newAddress);
      return new Response("Update Success: " + newAddress, { status: 200 });
    }

    return new Response("Not Found", { status: 404 });
  },
};
```


2. NATMap触发脚本
```bash
#!/bin/sh

# natmap 传入的参数
PUBLIC_IP=$1
PUBLIC_PORT=$2

if [ -z "$PUBLIC_IP" ] || [ -z "$PUBLIC_PORT" ]; then
    echo "Error: Missing IP or Port"
    exit 1
fi

# ================= 你的配置区 =================
# 替换为你的 Worker 域名和刚刚设定的 Token
WORKER_URL="https://你的worker前缀.你的用户名.workers.dev"
SECRET_TOKEN="你的自定义密码"
# ==============================================

# 拼接为 IP:端口 格式
PAYLOAD="${PUBLIC_IP}:${PUBLIC_PORT}"

# 发送 POST 请求至 Cloudflare Worker
curl -s -X POST "${WORKER_URL}/update" \
  -H "Content-Type: text/plain" \
  -H "Authorization: Bearer ${SECRET_TOKEN}" \
  -d "${PAYLOAD}"

# 记录本地日志
echo "$(date): Updated natmap address to ${PAYLOAD}" >> /var/log/natmap_update.log
```

3. SubStore脚本
```js
async function operator(proxies) {
    // ================= 你的配置区 =================
    // 替换为你的 Worker 订阅地址和 Token
    const apiUrl = "https://你的worker前缀.你的用户名.workers.dev/sub?token=你的自定义密码";
    
    // 你在 Sub-Store 里建的那个基础代理节点的名字
    const targetNodeName = "Home_Intranet";
    // ==============================================

    try {
        // 请求 Cloudflare API 获取最新 IP:端口
        const response = await fetch(apiUrl);
        if (!response.ok) {
            throw new Error(`HTTP Error: ${response.status}`);
        }
        
        const data = await response.text();
        const parts = data.trim().split(":");
        
        if (parts.length === 2) {
            const newIp = parts[0];
            const newPort = parseInt(parts[1], 10);
            
            // 遍历所有节点，精准狙击并覆写目标节点
            proxies.forEach(proxy => {
                if (proxy.name === targetNodeName) {
                    proxy.server = newIp;
                    proxy.port = newPort;
                    // 可选项：动态修改节点名称，在客户端直观展示当前连的哪个端口
                    proxy.name = `${targetNodeName} [${newPort}]`;
                }
            });
        }
    } catch (e) {
        // 请求失败时静默捕获，Sub-Store 将使用原基础节点的配置(或缓存)
        console.log("Fetch natmap port failed: " + e.message);
    }
    
    // 必须返回原数组，让 Sub-Store 继续后续流水线
    return proxies;
}
```
